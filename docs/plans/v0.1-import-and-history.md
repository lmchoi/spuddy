# Plan: v0.1 — Import and History

## Goal
A user can paste a Liftosaur workout text after a session (or import a JSON backup once), see the parsed data before saving, and browse their exercise history by exercise.

## Out of scope
- Session logging (v0.2)
- Progression charts — deferred to v0.2 when there's real data to visualise
- Smart progression engine (v0.3)
- Program view (no logging yet, so no need to see the program)
- Garmin, camera, Apple Health
- Progression suggestions

**Note on PRD:** PRD lists progression charts under v0.1, but without logging there won't be enough data to make them meaningful. Deferring to v0.2 where they'll be built alongside session logging.

## Research findings
See `docs/ideas/liftosaur-format-research.md` for full detail. Summary:

- **Two parsers needed:** text format (daily paste flow) and JSON backup (one-time bootstrap)
- **Text format:** custom line-based, `field / field / exercises: { ... }`. Equipment embedded in exercise name (appended only when non-default, e.g. "Lunge, Dumbbell")
- **JSON format:** `IStorage` object — `storage.history[]` has all sessions; `entry.exercise.equipment` is an explicit field
- **Internal model:** both parsers produce the same `Session` type
- **`+` tab title is intentionally blank** — raised circle icon looks wrong with a text label beneath it

## Navigation
`Progress | + | Settings`

- **Progress** — exercise list; tap an exercise → session history for that exercise
- **+** (centre tab, no title) — paste Liftosaur text → preview parsed data → adjust → save
- **Settings** — JSON backup import, equipment profile, JSON export + AI prompt

## Steps

### 1. Internal data model
**What:** Define TypeScript types for `Session`, `ExerciseEntry`, `WorkingSet`. No storage yet — just types in `src/types.ts`.

**Tests:** Type-only — no runtime tests needed here. TypeScript compiler is the test.

**Commits:**
- `feat: add core domain types (Session, ExerciseEntry, WorkingSet)`

---

### 2. Liftosaur text parser
**What:** Pure function `parseLiftohistoryText(text: string): Session`. Handles all the format variants from the research doc: rep ranges, warmup sets, unilateral, AMRAP, RPE, rest timer, bodyweight (0kg).

**Tests first:**
- Parses the real example from the user's export (Face Pull, Goblet Squat, Lunge, Romanian Deadlift, Plank)
- Rep range: `3x10-12 14kg 60s`
- Unilateral: `1x3|3 11kg`
- Warmup sets separated correctly
- Bodyweight (`0kg`) flagged as bodyweight
- Missing target → no target on set
- Malformed input → returns error

**Commits:**
- `test: text parser — real export, edge cases`
- `feat: implement Liftosaur text format parser`

---

### 3. Liftosaur JSON backup parser
**What:** Pure function `parseLiftohistoryJson(json: unknown): Session[]`. Reads `storage.history[]` from the full JSON export.

**Tests first:**
- Parses a fixture JSON with 3 sessions
- Equipment field mapped correctly
- warmupSets separated
- Skipped sets (completedReps === null) excluded

**Commits:**
- `test: JSON backup parser — fixture data, equipment, skipped sets`
- `feat: implement Liftosaur JSON backup parser`

---

### 4. Add screen — paste and preview
**What:** The `+` tab screen. Two sections stacked vertically:
- Top: multiline text input ("Paste your Liftosaur workout here")
- Bottom: live preview of parsed session (exercise name, sets × reps @ weight, target)
- Footer: "Save" button (disabled until parse succeeds)
- Error state shown inline if parse fails

Design note: invoke `frontend-design` skill when implementing this screen.

**Tests first:**
- Renders text input
- Typing valid text shows parsed preview
- Typing invalid text shows error message
- Save button disabled when input is empty

**Commits:**
- `test: Add screen — input, preview, error state, save button`
- `feat: Add screen — paste input with live parsed preview`

---

### 5. Local storage (SQLite)
**What:** `src/storage/db.ts` — expo-sqlite wrapper. Schema: `sessions` table. Functions: `saveSession(session)`, `getAllSessions()`, `getSessionsForExercise(exerciseName)`.

**Tests first:** Integration tests using a real in-memory SQLite DB (not mocked).
- Save a session → retrieve it
- Multiple sessions → ordered newest first
- Query by exercise name

**Commits:**
- `test: SQLite storage — save, retrieve, query by exercise`
- `feat: SQLite storage layer`
- `feat: wire Add screen Save button to storage`

### 6. Progress tab — exercise list
**What:** List of unique exercises the user has logged, sorted alphabetically. Tapping an exercise navigates to a detail screen showing all logged sessions for that exercise (newest first). Each row: date, sets × reps @ weight, on-target indicator (hit / below / exceeded).

Design note: invoke `frontend-design` skill when implementing these screens.

**Tests first:**
- Exercise list renders exercises from storage
- Empty state when no sessions
- Exercise detail shows sessions for that exercise only, newest first
- On-target indicator correct for hit, below, exceeded

**Commits:**
- `test: Progress tab — exercise list, empty state`
- `feat: Progress tab — exercise list screen`
- `test: Exercise detail — sessions list, on-target indicator`
- `feat: Exercise detail screen`

### 7. Settings — JSON backup import
**What:** File picker (expo-document-picker) on the Settings screen. Reads the Liftosaur JSON file, parses it with the JSON parser from Step 3, bulk-inserts into SQLite. Shows progress and result (N sessions imported).

**Tests first:**
- Import fixture JSON → sessions appear in storage
- Duplicate import → sessions not duplicated (dedup by date + programId + day)
- Malformed JSON → error message

**Commits:**
- `test: JSON backup import — bulk insert, dedup, error handling`
- `feat: Settings — JSON backup import`

---

### 8. Settings — Equipment profile
**What:** Form to define available equipment: adjustable dumbbells (specify weight increments), resistance bands (toggle), bodyweight (always on), pull-up bar (toggle), bench (toggle), barbell (toggle with plate list).

This data is used by the progression engine (v0.3) — store it in SQLite but don't act on it yet.

**Tests first:**
- Renders all equipment fields
- Saves and reloads equipment profile

**Commits:**
- `test: equipment profile — render, save, reload`
- `feat: Settings — equipment profile`

### 9. Settings — JSON export and AI prompt

- "Export JSON" → serialises all sessions → share sheet (expo-sharing)
- "Copy AI prompt" → copies a coaching prompt template with recent session data to clipboard

**Tests first:**
- Export produces valid JSON with all sessions
- AI prompt includes last 3 sessions and key metrics

**Commits:**

# Plan: v0.3 — Session Logging

**Status: in progress**

## Goal

A user can log a workout session against their active program day — recording sets, reps, and weight in real time — and see the completed session in the progress detail view immediately after.

## Carry-forward from v0.2 / bento redesign

These gaps must be resolved in this milestone (or explicitly deferred with a reason):

**Data model gaps that stub out bento tiles:**
- `Session.durationMin` — needs `startedAt` / `endedAt` timestamps on Session. Unlocks the Duration bento tile.
- `Session.programDay` — needs a link from a saved session back to the program day it was logged against. Unlocks the subtitle in the header and the program day label.
- `ExerciseEntry.muscleGroup` — needs muscle group tags on exercises (import from program or manual). Unlocks the muscle-group list in the Exercises section heading.
- `ExerciseEntry.isPR` / `prNote` — needs cross-session PR detection (rep PR, weight PR). Unlocks the PR bento tile and the gold PR badge on exercise rows.

**Display gaps introduced by the bento redesign:**
- `WorkingSet.repsLeft` is stored and parsed but never shown in the session detail screen. Unilateral exercises (single-leg, single-arm) silently drop the left-side rep count. Needs a display decision before unilateral logging is promoted.
- Warmup sets are no longer surfaced in the session detail view. The old screen showed "N warmup sets". Revisit once the live logger is built — warmups matter more there.

**Pre-existing carry-forward (from v0.2 plan):**
- Android `content://` URI gap in program import — `fetch(uri)` unreliable for local files on Android. Fix when Android testing begins.
- ~~ActivityStrip UTC bug~~ — fixed in progress-streak-hero PR (`localDateStr()` helper used everywhere session dates are compared).

**Palette centralisation:** ✓ resolved
- Moved to `components/spuddy/palette.ts` (done in add-workout slice 1). Note: landed in `components/spuddy/` rather than the originally planned `constants/Colors.ts` — both add screen and tab bar pill now import from there.

### Slice 2 — Session logger domain (`src/domain/sessionLogger.ts`) [ ]

Pure functions, no React. Fully unit-tested before any UI exists.

**State shape:**

```ts
type LoggedSet = { reps: number; weight: number };

type SessionState = {
  loggedSets: LoggedSet[][];  // [exerciseIdx][setIdx] — full history, never reset on exercise switch
  currentExerciseIdx: number;
  isResting: boolean;
  startedAt: number;          // Date.now() captured at session start
};
```

**Functions to implement:**
- `initSession(day: ProgramDay): SessionState`
- `logSet(state, exIdx, reps, weight): SessionState` — appends to `loggedSets[exIdx]`, sets `isResting: true` if more sets remain in that exercise
- `skipRest(state): SessionState`
- `jumpToExercise(state, idx): SessionState` — switches `currentExerciseIdx`, clears `isResting`
- `isExerciseDone(state, day, exIdx): boolean`
- `isSessionDone(state, day): boolean`
- `getActiveTarget(state, day, exIdx): Target` — returns the next unlogged set's target for pre-populating steppers; defaults reps to 10 when target has no reps specified
- `buildSavePayload(state, day, date): Session` — assembles the `Session` object ready for `saveSession`

**Tests cover:** init state, logging all sets for an exercise, jumping between exercises (logged values persist), finishing the session, save payload structure, default reps fallback.

### Slice 3 — `app/log-session.tsx` screen [ ]

Accepts `programName` + `dayIndex` as Expo Router search params. Loads `ProgramDay` via `getProgramDay`. All state driven by the domain functions from Slice 2.

**Sub-components (extracted within the file):**
- `ExerciseStrip` — completion dots derived from `loggedSets[i].length` vs `targets.length` (not a mutable counter)
- `SetList` — past logged sets show real values; active set highlighted; future sets dimmed
- `StepperPair` — reps + weight, weight snapped to equipment steps array
- `RestTimer` — countdown with skip
- `BottomAction` — log set / next exercise / finish session

**On "Finish session":** `buildSavePayload` → `saveSession` → `router.replace('/progress/[date]')`.

**Tests cover:** renders with a mocked `ProgramDay`, logging a set updates the set list, finishing saves and navigates.

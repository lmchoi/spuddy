# Liftosaur Export Format Research

Researched from the liftosaur-clone source (`src/liftohistory/liftohistorySerializer.ts`, `src/lib/importexporter.ts`, `src/types.ts`, `src/models/exercise.ts`).

## Two export formats — both needed

| Format | When used | How triggered |
|---|---|---|
| **Text** ("Copy as Text") | After every workout | Share button → "Copy as Text" → paste into Spuddy |
| **JSON backup** | Once, for history bootstrap | Settings → Export → `liftosaur-YYYYMMDD.json` |

Both parsers produce the same internal data model. The text format is the **day-to-day driver**; JSON is a one-time bootstrap.

---

## Text format (per-session)

Generated by `LiftohistorySerializer_serialize`. Custom line-based format:

```
2026-05-19 19:20:52 +01:00 / program: "starter" / dayName: "Day 1" / week: 1 / dayInWeek: 1 / duration: 2811s / exercises: {
  Face Pull / 1x20 9kg, 1x18 9kg, 1x20 9kg / target: 3x15-20 10kg 45s
  Goblet Squat / 1x6 13.5kg, 2x10 13.5kg / warmup: 1x5 13.5kg / target: 3x10-12 14kg 60s
  Lunge, Dumbbell / 1x3|3 11kg / target: 2x10 60s, 1x10 10kg 60s
  Romanian Deadlift / 3x10 22kg / warmup: 1x5 11kg, 1x5 17kg / target: 3x10-12 22kg 60s
  Plank / 3x30 0kg / target: 3x30 45s
}
```

### Header fields (` / ` delimited)
- `date` — `YYYY-MM-DD HH:MM:SS ±HH:MM`
- `program: "name"` — omitted for ad-hoc workouts
- `dayName: "Day 1"` — multi-week programs only
- `week: N` / `dayInWeek: N` — multi-week programs only
- `day: N` — single-week programs (alternative to week/dayInWeek)
- `duration: Ns` — in seconds

### Exercise line fields (` / ` delimited)
- **Name** — full name, see equipment note below
- **Completed sets** — `NxR W`, e.g. `1x20 9kg, 1x18 9kg, 1x20 9kg`
- `warmup: sets` — optional, same format
- `target: sets` — target with rest, e.g. `3x15-20 10kg 45s`

### Set notation
- `NxR W` — N sets × R reps at W kg (groups consecutive identical sets)
- `NxMIN-MAX W Ts` — rep range + weight + rest timer
- `NxR|L W` — unilateral: R reps right, L reps left
- `NxR+ W` — AMRAP (as many reps as possible)
- `NxR W @RPE` — with RPE
- Weight `0kg` = bodyweight exercise

### Equipment in exercise names
`Exercise_fullName` appends equipment only when it differs from the exercise's default:
- `"Romanian Deadlift"` → barbell (its default, so not appended)
- `"Lunge, Dumbbell"` → dumbbell (non-default for Lunge)
- `"Plank"` → bodyweight (default)
- `"Face Pull"` → cable/band (default for Face Pull)

**Implication:** to fully resolve equipment from the text format, you'd need the Liftosaur exercise database. For v0.1, treat the full name (including any `, Equipment` suffix) as the exercise key. Equipment resolution can be improved later.

## JSON backup format (`IStorage`)

Full state dump. Top-level structure:

```json
{
  "history": [ /* IHistoryRecord[] */ ],
  "programs": [ /* IProgram[] */ ],
  "settings": { "exercises": { /* custom exercises by id */ }, "units": "kg", ... },
  "currentProgramId": "starter",
  "version": "20240101",
  ...
}
```

### Session record (`IHistoryRecord`)
```json
{
  "date": "2026-05-19T19:20:52+01:00",
  "programId": "starter",
  "programName": "starter",
  "day": 1,
  "dayName": "Day 1",
  "week": 1,
  "dayInWeek": 1,
  "startTime": 1748000000000,
  "endTime":   1748002811000,
  "entries": [ /* IHistoryEntry[] */ ],
  "notes": "optional"
}
```

### Exercise entry (`IHistoryEntry`)
```json
{
  "exercise": { "id": "lunge", "equipment": "dumbbell" },
  "sets": [ /* ISet[] — working sets */ ],
  "warmupSets": [ /* ISet[] */ ],
  "notes": "optional"
}
```

Equipment IS a separate field in the JSON — no name parsing needed.

### Set (`ISet`)
```json
{
  "reps": 12,
  "minReps": 10,
  "weight": { "value": 14, "unit": "kg" },
  "timer": 60,
  "isAmrap": false,
  "isUnilateral": false,
  "completedReps": 10,
  "completedRepsLeft": null,
  "completedWeight": { "value": 13.5, "unit": "kg" },
  "completedRpe": null
}
```

Target and completed live in the same object. `completedReps == null` means the set was skipped.

## What we parse for v0.1

Both formats feed into the same `Session` model:

| Field | Text format | JSON format |
|---|---|---|
| Date | Header timestamp | `record.date` |
| Program name | Header `program:` | `record.programName` |
| Day name | Header `dayName:` | `record.dayName` |
| Duration | Header `duration:` | `endTime - startTime` |
| Exercise name | Line name (with equip suffix) | Resolved from exercise id |
| Equipment | Embedded in name (partial) | `entry.exercise.equipment` |
| Completed sets | Line completed section | `set.completedReps/Weight` |
| Target sets | Line `target:` section | `set.reps/weight/timer` |
| Warmup sets | Line `warmup:` section | `entry.warmupSets` |

## Open questions

- Bodyweight exercises: `weight.value === 0` appears to be the signal in both formats (`0kg` in text, `{ value: 0 }` in JSON). Needs confirmation with a real export.
- Custom exercises: JSON stores them in `settings.exercises`, referenced by ID. Text format just uses their full name. If the user has custom exercises, name matching may be needed for deduplication.
